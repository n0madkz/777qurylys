# Категории сайта и сопоставление 1С

После развёртывания: админка → Категории → «Распределить товары».
Создаётся дерево разделов сайта. Товары с группами 1С или без категории
распределяются по названию и исходному пути группы. Ранее назначенные
автоматические категории shop-* также исправляются. Вручную изменённые
в карточке категории отмечаются metadata.category_manual и сохраняются.
Фото, текст, характеристики, остатки и статус не меняются.

Новые товары при импорте получают категорию сайта автоматически и остаются
неактивными. Группы 1С сохраняются скрытыми для контекста. Классификация
эвристическая: для новых нераспознанных товаров остаются общие разделы,
с отметкой metadata.category_review. Отчёт локальной проверки:
reports/product-categories.csv. В проверенной выгрузке 3943 товара,
все получили категорию из 114 узлов дерева (разделы и подкатегории).
Нераспознанных на этой выгрузке нет; новые товары могут потребовать проверки.

Сопоставление импорта: сначала уникальный metadata.code из 1С. При совпадении
кода сохраняется прежний ID карточки сайта, даже если GUID 1С изменился.
GUID также используется для совместимости с уже существующими карточками.
При конфликте кода с другой карточкой или дублях кода импорт выдаёт ошибку,
чтобы исключить случайное обновление чужого товара.

Для новых товаров все строки одного пакета имеют одинаковые поля, включая
brand (пустая строка, если бренд не определён). Это устраняет ошибку
PostgREST «All object keys must match».
