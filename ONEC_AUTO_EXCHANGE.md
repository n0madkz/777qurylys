# Автоматический обмен 1С → сайт

Адрес: `https://777qurylys.kz/api/1c-exchange`
Подготовлен обработчик штатного протокола CommerceML: checkauth, init, file,
import (порциями по 25 товаров, progress/success). Реальный запуск требует
настройки Plesk и 1С и успешного контрольного обмена.

## Plesk

Получить и развернуть Git. В существующий `.777qurylys.env` добавить:

```ini
ONEC_EXCHANGE_USER=onec_catalog
ONEC_EXCHANGE_PASSWORD=ЗАМЕНИТЬ_НА_СЛУЧАЙНЫЙ_ПАРОЛЬ_НЕ_КОРОЧЕ_24_СИМВОЛОВ
```

Создать новый случайный пароль в менеджере паролей и ввести его в Plesk и 1С.
Пароль админки не использовать. Файл в Git не добавлять. После настройки
открытие адреса с `?type=catalog&mode=checkauth` без логина должно давать
401; до настройки — 503 «Обмен 1С ещё не настроен на сервере».
Сервер должен передавать Authorization в PHP; правило добавлено в .htaccess.
При 401 с правильными данными проверить настройку PHP/FastCGI в Plesk.

## 1С

Лучше создать отдельную настройку обмена, сохранив существующую выгрузку в папку.
Тип сайта: «1С-Битрикс», направление «На сайт», адрес обработчика выше.
Логин и пароль — из серверного файла. Фото, присоединённые файлы,
заказы, услуги и загрузку данных с сайта отключить. Это обмен только каталогом.
Товары, предложения и разбивку по складам включить. Выбрать розничный вид цен
для проверки штатной 1С; ограничение «только с ненулевой ценой» выключить.
Цены из предложений в товарную базу сайта не сохраняются.

Нужна ПОЛНАЯ выгрузка import.xml + offers.xml за каждый запуск.
Включить полный обмен ежедневно. Один каталог, имена файлов import.xml и
offers.xml, без фото и ZIP. Дельты, отдельная отправка offers.xml, форматы
с разбиением import0_1.xml и несколько каталогов пока не поддерживаются.
Сначала выполнить проверку подключения и ручную полную синхронизацию.
При другом имени файла или схеме отправки сохранить текст ошибки для адаптации.

После успешной проверки включить периодический полный обмен:
каждый день, один раз в 01:00 ПО ВРЕМЕНИ АСТАНЫ (UTC+5).
Обязательно сверить часовой пояс сервера 1С: если UTC+6, запуск в 02:00
его локального времени соответствует 01:00 по Астане. RDP можно отключить;
сервер и служба 1С должны работать, регламентные задания базы разрешены.

## Проверка

Сверить остаток 2–3 товаров с отчётом 1С, включая товар с нулевым остатком.
Изменить один остаток и повторить обмен: число карточек не увеличивается,
количество обновляется, выбранные вручную категории, активность и фото
сохраняются. Новый товар появляется скрытым. В админке есть дата обновления
остатков. Проверить историю задания в 1С на следующий день после 01:00.

«Магазин склад1» исключается по ID и имени в API, импорте и таблице.
Его запись в самой 1С не удаляется. Отсутствующие товары не удаляются и
не обнуляются: для нулевого остатка 1С должна передать предложение с нулём.

## Временные файлы

CommerceML при передаче порциями временно собирается в закрытой системной
temp-папке сервера вне сайта. Это включает ценовые блоки исходного offers.xml.
Они не переносятся в товарную базу или публичное хранилище. Оба XML удаляются
после успешного импорта; незавершённые сессии старше трёх часов очищаются
при следующем авторизованном обмене. Не добавлять тела запросов обмена
в журналы reverse proxy/APM. Публикация/удаление товаров остаются ручными.
