# Заявки в приватный Telegram-канал

1. Создайте бота в официальном @BotFather командой `/newbot`. Токен храните только на сервере.
2. Создайте приватный канал, добавьте бота администратором с правом публикации сообщений.
3. Опубликуйте в канале обычное сообщение. Получите `channel_post.chat.id` через метод Bot API `getUpdates` (если у бота не настроен webhook). Числовой ID канала имеет вид `-100...`. Ссылка-приглашение вместо ID не подходит. Не отправляйте токен сторонним ботам и сайтам для определения ID.
4. В Plesk откройте файл `.777qurylys.env` **выше каталога httpdocs**, где уже находятся настройки Supabase. Добавьте:

```ini
TELEGRAM_BOT_TOKEN="токен от BotFather"
TELEGRAM_CHAT_ID="-100..."
```

5. Разверните код через Git в Plesk.
6. Добавьте в Plesk планировщик задач: **Выполнить PHP-скрипт**, PHP той же версии, что у сайта; путь `httpdocs/scripts/telegram-deliver.php`, расписание каждую минуту (`* * * * *`). При необходимости используйте абсолютный путь к скрипту. Скрипт работает только из CLI.
7. Отправьте одну тестовую заявку через сайт: она должна появиться в админке и канале. Удаление тестовой заявки из админки не удаляет сообщение из канала.

Сайт пробует отправить уведомление после сохранения заявки. Планировщик повторяет отправку из приватной папки `.777-telegram-queue` выше httpdocs. PHP сайта и планировщика должны иметь права чтения настроек и записи в эту папку. `TELEGRAM_QUEUE_PATH` позволяет задать другой приватный абсолютный путь. В очередь попадают также заявки, созданные до настройки бота после развёртывания этого кода.

В канале: имя, телефон, email/компания при наличии, комментарий, товары с количеством и названия приложенных файлов. Для скачивания файлов нужна авторизация в админке. Цены и банковские реквизиты в Telegram не отправляются. Длинная заявка разбивается на несколько сообщений. Успешно отправленные части повторно не отправляются при обычном повторном запуске планировщика. После подтверждения всей заявки очередь удаляет её файл.

При неоднозначном сетевом таймауте Telegram мог уже принять сообщение: повторная попытка иногда создаёт дубль. Номер заявки позволяет его распознать. При ошибке записи очереди заявка остаётся в админке, а в журнал PHP пишется номер заявки. Следите за ошибками PHP и задач планировщика.

Документация: https://core.telegram.org/bots/api#sendmessage
